# GS-002 — Live local AI communication

GS-002 connects `qwen2.5-coder:3b` through the GS-001 Administrator and Orchestrator bridge. Qwen accepts only `explanation`, `assessment`, and `code_proposal` requests. It returns text and identifying metadata; it has no tool interface, filesystem operation, approval authority, or production-write authority.

## Security changes

- New submissions default to `approval.status = pending`. The Administrator must call `approve(task_id, owner=...)` before the Orchestrator can claim them.
- Workers run in a dedicated subprocess. On timeout the Orchestrator kills that process and records a retryable `execution_timeout`, avoiding the previous non-cancellable thread behavior.
- The Ollama adapter rejects non-loopback endpoints.
- The Qwen descriptor grants only `read` and `propose`; a task requesting `write` fails authorization before inference.
- The system prompt explicitly denies tools, file modification, operational approval, and Pyrene P2.5 gameplay authority.
- There is no cloud fallback or paid API integration.
