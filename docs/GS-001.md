# GS-001 — Existing local-agent connection

## Reused Administrator infrastructure

- `orchestrator/task_queue.py`: authoritative JSON task records, atomic writes, exclusive claim files, ownership, leases, heartbeats, retry budgets, timeout recovery, and terminal states.
- `operations/task_reporting.py`: private task report materialization and sanitized, idempotent external outbox.
- `operations/github_issue_adapter.py` and `operations/run_github_integration.py`: established intake/routing and owner-approval policy remain unchanged.
- `config/workflow.json`: localhost-only Ollama endpoint, disabled Ministral orchestrator, read-only Granite policy, path allowlists, and production-apply gate.
- `orchestrator/autonomous_workflow.py`: existing command entry points and Qwen/Granite adapters remain the implementation for model-backed work.

Ground Space dynamically loads `PersistentQueue`; it does not copy or replace queue, lease, approval, scheduling, or reporting logic.

## Adapter contract

`AdministratorAdapter.submit()` creates a normal queue record enriched with a correlation ID, requested worker, permission requirements, explicit approval state, and execution timeout. `OrchestratorAdapter.process()` claims through the existing queue, enforces approval and worker permissions, emits structured acknowledgement/progress/completion/failure messages, then finishes or retries through the existing queue API.

Messages are versioned JSON records containing a unique message ID, task ID, correlation ID, UTC timestamp, sender, recipient, type, and payload. They are appended to `messages.jsonl`. Duplicate delivery of a terminal task is idempotent and audited.

## Safety boundary

The deterministic Python worker accepts only `read` permission and returns only a canonical payload hash and key inventory. It has no filesystem target or mutation operation. Qwen is declared proposal-only, Granite read-only, and Ministral inactive. No cloud client exists in this project.
