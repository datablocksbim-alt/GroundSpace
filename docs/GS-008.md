# GS-008 — Premium chat and planning-aware slash notes

## Chat interface

- Keep user and AI chat bubbles soft, rounded and legible; preserve periwinkle planning cards.
- Scale sidebar AI glyphs down to compact 27 × 24 pixel, subtly rounded rectangular badges.
- Use thin, low-contrast chat/sidebar/picker scrollbars which become easier to see on hover.
- Keep keyboard and mouse-wheel scrolling functional and avoid hiding scrollbar affordances completely.

## Planning command behavior

Typing `/goal <description>` or `/milestone <description>` saves a structured note as before. In a direct local-model chat it now queues a bounded planning proposal from the selected installed model. In a group it queues a separate proposal from each configured member, processed sequentially. Each note keeps its original periwinkle card and displays proposal task status; assistant replies appear below under the model identity. This is not an execution command.

The planning prompt asks the AI to interpret the objective, suggest milestones or acceptance criteria, and identify the next step. It does not instruct an AI to write files, run commands, or claim it completed work. Queue tasks retain permissions `read` and `propose`; no new filesystem permissions, tools, cloud connectors, or API payments are enabled. Administrator-console notes remain record-only.

Up to 12 recent saved planning notes are included alongside the eight latest normal messages when forming bounded context (capped at 8,000 characters). This keeps active project goals available after ordinary chat messages scroll past, but it is not a replacement for a proper Administrator-goal lifecycle.

## What this does not yet implement

- Goal assignment to specific workers or project files.
- Autonomous execution or approval to alter projects.
- Status transitions for actual project milestones.
- Administrator-driven decomposition of work into agent tasks.

Those are separate Administrator integration features to design and permission-gate.
