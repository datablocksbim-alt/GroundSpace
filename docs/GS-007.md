# GS-007 — Multi-model group chats and local project selector

## Group chats

Create a named group under **Chat → Group chats → + New**. Choose up to **six registered Ollama models**, optionally link a project, and open the group from the sidebar. Under **Members**, edit the AI roster or change the group's project later.

When the user sends a group message, Ground Space records **one user turn** and queues one proposal-only task per participating model using the existing Administrator queue. It dispatches those tasks **sequentially**, to avoid concurrent GPU saturation on a laptop. Every model receives the same bounded conversation context and original request, and returns its own clearly labeled message. The group view shows per-model queue/running/retry/completion states, and existing Copy Response works for each reply.

This initial version is *not* an autonomous debate or unrestricted multi-agent team. Models do not call each other, have filesystem write tools, or make policy decisions. Adding a model to a group does not qualify it for autonomous coding work. An offline worker is shown as unavailable, and its queue error is recorded instead of hiding the failure. All current group inference runs through local Ollama only; ChatGPT and Claude still require future provider connections.

## Select local project

Use **Projects → + Folder** to open a local folder picker, navigate permitted directories, or paste an absolute path. Ground Space verifies it is an existing folder **inside an explicitly allowed root**, saves its canonical path in the private Project registry, and lets users select it in direct chat or when creating/editing a group.

Allowed roots default to the existing Data Blocks project directory's parent and the Windows account home folder. To authorize other project directories, set **GROUND_SPACE_ALLOWED_PROJECT_ROOTS** to a semicolon-separated list of trusted absolute paths (Windows) before starting Ground Space.

Example:

```powershell
$env:GROUND_SPACE_ALLOWED_PROJECT_ROOTS = "D:\000_AI Project;E:\Projects"
.\tools\start_ground_space.ps1
```

A project is currently a **workspace association**: its ID is attached to messages and Administrator task metadata. Local Ollama prompts also receive the registered project name and absolute folder path as an explicit metadata-only context block, so agents can identify which project the conversation concerns. Each direct project/channel combination has separate conversation history; every group has its own conversation history and project association.

**Security boundary:** Adding/selecting a project does **not** give the AI read/write access to that folder, execute commands, upload files, or enable automatic coding. The path is identity metadata for the local model, not an authorization or file attachment. Actual project file work needs a separate, audited and permission-limited worker adapter with a per-project allowlist. Group chat remains localhost-only and zero-API-cost.

The folder browser lists only directory names beneath allowed roots (no file contents). Path verification resolves symlinks before enforcing allowed-root containment, disallows registering a root itself, and persists data under the private state folder rather than GitHub. Projects and group chat metadata survive server restart.
