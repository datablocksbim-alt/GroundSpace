# GS-029 — Browse and select project folders

**Status:** Candidate, not deployed. Based on GS-028 project-first navigation.

## Owner-requested behavior

Add Project now opens a compact browser of **folders on the ASUS** immediately. Users on an iPhone can navigate those ASUS folders remotely through Ground Space. The workflow is:

1. **Projects → + Project** opens the list of permitted ASUS project roots. No address entry is required.
2. Tap a folder to browse within it. **Back** navigates upward; **Roots** returns to permitted folders.
3. In a subfolder, tap **✓ Select this folder**. The selected path appears as read-only confirmation, with a **Change** action.
4. Optionally change the project display name; press **Add project**. Its button is disabled until a selection is made.

The folder path field is hidden and filled only by the selection action. Backend `WorkspaceRegistry.browse_folders()` and `add_project()` continue to enforce real-directory and allowed-root restrictions. Project linking remains `metadata_only`; no AI automatically gains filesystem permissions.

This uses Ground Space's authenticated server-side ASUS folder browsing. It **does not** open the iPhone Files picker or a native Windows Explorer dialog. That distinction is necessary because the browser is on an iPhone while the project folders live on the ASUS. The existing server-side browse API returns a maximum of 100 immediate children per folder; it does not enumerate an entire disk.

Existing projects, nested chats, messages, approvals and agents are unaffected. This is a front-end improvement with no state migration.

## Verification

CI covers Windows and Ubuntu Python regressions, folder path enforcement and iPhone-size/desktop Chromium navigation, including change-selection behavior and enabled/disabled Add states. Physical iPhone Safari remains a separate visual acceptance gate.
