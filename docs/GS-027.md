# GS-027 — Compact per-agent configuration (candidate)

**Status:** Candidate on `feature/gs-027-unified-agent-configuration`; not deployed.  
**Base:** GS-026 `feature/gs-026-mobile-agent-model-controls`.  
**Owner boundary:** Single-owner, loopback-only server behind the pre-existing private Tailscale route.

## UX

Agents → Add Agent registers **installed Ollama models** or the **installed, owner-authorised Codex CLI**. Claude and Grok remain marked unconnected, not silently routed to a local model.

Each registered Agent is a compact expandable row:

- **Model:** available/registered Ollama IDs or explicit Codex CLI model names
- **Access:** multi-select (read/chat/propose/review for local Ollama; read/review/workspace coding for Codex)
- **Level:** Low/Medium/High, mapped to Fast/Balanced/Detailed for Ollama or supported Codex reasoning effort
- **Approval:** Off / automatic read-only for Ollama; Ask me / automatic read-only / Off for Codex
- **Save configuration:** persists on the server; refresh/reconnect/restart reloads the same configuration

The row is collapsed by default to preserve iPhone screen space. The saved summary remains visible without opening the controls. The composer keeps request-type options for compatibility; agent models and levels are primarily configured under **Agents**, not in chat.

## Persistence and execution

`private/agent_configs.json` is a new, versioned, atomically-written file. If absent, the legacy GS-026 registry, project/group memberships, Codex default profile and task history are left intact. New records are checked against registered models and fixed provider capability allowlists before writing.

Saved defaults apply to **new** tasks in direct chats, group chats and Co-work:

- A local agent's existing registry ID and group membership stay unchanged even when its execution model changes.
- Saved local model and response level resolve at dispatch; a newly submitted task records its actual model and level.
- Saved Codex model and effort affect future direct and Co-work jobs; legacy explicit group model overrides remain effective.
- New groups inherit per-agent approval defaults. Existing group-specific approval settings remain explicit overrides, subject to the agent's global disabled/restricted state.
- Tasks already queued, approved or running keep the original task snapshot; saving never silently changes their model or approval record.

The provider adapter and server sandbox are authoritative. **Workspace coding is an indivisible capability at present**: existing Codex CLI workspace-write can edit/run/delete within its approved sandbox; individual write/run/delete toggles would falsely imply separate enforcement, so GS-027 intentionally presents one combined selection. Server opt-in and existing approvals still apply. New GS-027-saved Codex settings cannot automatically approve a writable group or Co-work task. Older, explicitly authorised GS-026 group policies remain compatible until the owner changes their agent configuration.

## Known scope limits

- A registered local model retains its stable legacy agent ID. Creating *two separate named agents backed by the same Ollama model* is **not implemented** in this release; that requires a separate group/worker identity migration.
- `Add Agent` registers only **currently discovered** models and the installed Codex CLI. It does not install models, create provider credentials, connect Claude/Grok or support unrelated third-party skills.
- Manual approvals for direct local Ollama inference are not implemented. Use group-level Ask me, or the per-agent Auto read-only / Off choices. A server request for an unsupported local direct manual policy is rejected.
- There is no broad Apply-to-all-groups overwrite action. Existing per-group overrides are retained intentionally; global disabled/restricted capabilities remain effective.
- Verified CLI model entitlement and physical iPhone Safari still require ASUS-owner testing.

## Validation

GS-027 CI covers Windows and Ubuntu unit/regression tests and mobile-size/desktop Chromium interaction tests, including persisting an inline Level change across page reload. Server regression tests cover model registration boundaries, config restart persistence, group dispatch model/level resolution, and queued task snapshot immutability.

**Release gate:** Maintain GS-026 in production. Before activation, Codex must run ASUS-only integration tests, create and verify a fresh backup, test GS-026→GS-027 state restoration in an isolated state directory, and verify the actual iPhone Safari controls. No reboot, Tailscale, Pyrene, production state, or main-branch changes are approved by this implementation.
