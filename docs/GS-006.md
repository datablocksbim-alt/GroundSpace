# GS-006 — Soft chat bubbles and slash planning notes

## Appearance

- User messages: rounded, muted lavender-grey bubbles (dark text).
- AI responses: softly rounded pale-lavender/white bubbles, retaining the full-text **Copy response** button.
- `/goal` and `/milestone` messages: periwinkle bubbles, each with a subtle **GOAL** or **MILESTONE** label.
- Errors remain visually distinct; controls and composer have rounded corners.
- Chat remains responsive on compact screens.

## Using the commands

In **Chat**, type `/` to open the small command picker, choose a command, then write its description.

Examples:

```text
/goal Teach Python through a multi-island RPG.
/milestone Test live communication between Administrator and Qwen.
```

Select the command with a click, or press Enter while its suggestion is shown. Unknown slash commands or an empty description are rejected with an explanatory error.

Both commands create **structured conversation notes**, with `role=note`, `kind=goal|milestone`, `note_id`, timestamp, channel identity and content. They are written to the existing local conversations file and survive refresh and restart while within the bounded history retention window.

**Important boundary:** These are visible planning annotations, **not** Administrator project-queue tasks, global project milestones, automatic goal trackers or AI prompts. Creating them does not run inference, spend model tokens, start a worker, change Pyrene or grant permissions. Normal chat messages continue to use the existing approval-free, proposal-only worker path. A later milestone can link planning notes to the Administrator's actual goals and milestones after an explicit design and validation.
