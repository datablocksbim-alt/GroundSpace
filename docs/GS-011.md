# GS-011 — Verified local code proposals (draft)

This milestone adds a **reference implementation for QW-002** and an **explicit, owner-invoked code validation gate**. It does not give Coordinator, Qwen, or any Ground Space user authority to write project files or automatically execute generated Python.

## QW-002 reference fix

- Reference: examples/schedule_tasks.py
- Regression tests: tests/test_gs011_scheduler.py (10 tests)
- Independent acceptance contract: tests/fixtures/gs011_scheduler_contract.py (9 tests)
- Rules: Kahn's topological sort; highest priority among ready tasks; alphabetical ties; duplicate/missing/cycle errors; no input mutation. Duplicate entries in depends_on are treated as one requirement.
- Complexity: O(V + E + V log V) with V task IDs and E unique dependency edges.

Run trusted tests from the repository root:

    py -3 -m unittest tests.test_gs011_scheduler tests.test_gs011_validation -v

## Evaluate a Qwen-proposed schedule_tasks file

Save ONLY Qwen's proposed Python source to a local temporary file, for example \`C:\Temp\qw002_candidate.py\`. An owner must explicitly invoke:

    py -3 -m ground_space.proposal_validation "C:\Temp\qw002_candidate.py"

Results are machine-readable JSON with \`status\`: \`passed\`, \`failed\`, or \`blocked\`.

**Safety boundary:**
- This CLI is not called by the browser or Coordinator and never edits the project repository.
- Host process parses Python as syntax with \`ast.parse\`, but **never imports or executes** the candidate.
- Execution requires an existing local Docker daemon **and a locally cached** \`python:3.11-alpine\` image. The validator explicitly uses \`--pull never\` and will not download images.
- Candidate and the **fixed, trusted** acceptance contract are copied to a temporary directory mounted read-only inside the container. No other project, home or Administrator directories are mounted.
- Container has no network, read-only rootfs, non-root UID, dropped capabilities, no-new-privileges, CPU/memory/process limits, and a 30-second timeout with best-effort container cleanup.
- Missing Docker/image, syntax failure, or timeout does **not** become a pass. A passing reference implementation does **not** approve an untested Qwen submission.
- This is a **local developer benchmark**, not a hardened security boundary for malicious public submissions. Docker alone is not suitable isolation for untrusted public Pyrene player scripts; use disposable VMs/microVMs and independent security review before public rollout. Do not run unknown code outside the container.
- If Docker Desktop is unavailable on a resource-constrained laptop, the validator reports \`blocked\`; do **not** fall back to executing proposals on Windows.

If Docker is already installed and you intentionally want this gate, first inspect your local images:

    docker image inspect python:3.11-alpine

To preload the image, an owner may manually run \`docker pull python:3.11-alpine\` when a download is acceptable. Pulling is never automatic and incurs no paid model API calls.
