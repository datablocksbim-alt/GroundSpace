# GS-028 — Projects and Private AI chats

**Status:** Implementation candidate on `feature/gs-028-project-centric-chats`. This branch is based on GS-027, with no merge to `main` and no ASUS deployment by the GitHub implementation.

## Owner-requested navigation

The chat sidebar now has two top-level sections only:

- **Projects**: compact, expandable project folder rows. Expand a project to see its *existing* AI group conversations and a context-specific **+ New chat** action.
- **Private AI chats**: retained as a compact collapsible section below Projects, closed by default.

Group conversation functionality remains fully available: multiple AI agents, Coordinator routing, messages, approvals, per-group members, and Co-work. Only the *navigation* changes. Existing group `project_id`, `id`, `conversation_id`, message history and approval settings are consumed unchanged. **No data migration is made.**

Existing groups with no registered/matching project are shown in a **General · unassigned** folder inside Projects. New chats must select a real project, but existing unassigned chats remain readable and editable.

The project's local expansion preference is stored in browser-local `gs_expanded_project`; it is **not** a server project mutation. Refreshes and polling retain expansion state. The iPhone drawer is slightly narrower, with enough button/tap height and overflow handling.

## Out of scope

No Ollama installation, no additional cloud provider, no separate group tab, no new file permissions, no backend database conversion, no public/multi-user account feature. Other release branches and the original GS-026 backup remain unchanged.

## Tests

GS-028 CI includes previous GS-027/GS-026/security Python regressions on Windows and Ubuntu, plus Chromium mobile (390×844) and desktop interaction tests for existing project/group conversations, older unassigned chats, contextual new-chat creation, approvals, Co-work and Codex. Passing Chromium tests do **not** substitute for physical iPhone Safari acceptance.

## Non-destructive ASUS preview

Perform these commands on the ASUS in a maintenance-safe PowerShell session. Leave the existing Ground Space service on port 8765 and the existing private Tailscale route unchanged:

```powershell
$ErrorActionPreference = "Stop"
$source = "D:\000_AI Project\GroundSpace-GS027-Preview"
$preview = "D:\000_AI Project\GroundSpace-GS028-Preview"
if (Test-Path -LiteralPath $preview) { throw "Preview path already exists; inspect rather than overwrite" }
git -C $source fetch origin
if ($LASTEXITCODE -ne 0) { throw "Fetch failed" }
git -C $source worktree add --detach $preview origin/feature/gs-028-project-centric-chats
if ($LASTEXITCODE -ne 0) { throw "Worktree creation failed" }
Set-Location $preview
.\tools\prepare_gs028_preview.ps1
# After the precheck passes:
.\tools\prepare_gs028_preview.ps1 -StartPreview
```

Open `http://127.0.0.1:8780` **inside a browser on the ASUS** (e.g., through Chrome Remote Desktop from iPhone). This is desktop-only and uses `%LOCALAPPDATA%\DataBlocks\GroundSpace-GS028-Preview` state, **not** real chats from the live system. The automated browser fixture checks preservation with representative existing records.

Do not repoint Tailscale to the preview and do not replace production with the preview. Stop the preview with Ctrl+C. Physical Safari testing with real messages requires a separately guarded, owner-approved cutover once the preview passes.

## Release gate

1. CI green, and owner visually accepts iPhone-sized ASUS preview.
2. Confirm latest live GS-027 or GS-026 identity, zero running jobs, and verified fresh state backup on ASUS.
3. Restore **a copy** of the backup into an isolated GS-028 instance and validate all IDs/counts, approval modes and associations.
4. Only then perform guarded production activation and physically test the existing iPhone Safari Tailscale endpoint. Preserve the previous release checkout and backup; do not merge `main`.

GS-028 has **no automated production cutover** and no remote ASUS modifications from this PR.
