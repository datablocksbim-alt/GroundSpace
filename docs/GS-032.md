# GS-032 — Local coding-agent communication

Ground Space is the control plane, not the coding-agent implementation. It owns
the persistent task, approval, selected-project boundary, status, and audit trail.
Installed coding agents own their internal inspect/plan/edit/test/repair loop.

## Runtime contract

- `Qwen Code` is the first qualified local agent runtime. It is distinct from an
  Ollama `qwen*` model, which remains a chat/proposal worker.
- Chat and review turns launch Qwen Code in `plan` approval mode.
- A `workspace_change` turn launches it only after the group's persisted access
  mode is `full_write` and the existing manual or per-group approval policy has
  authorized that task.
- The process working directory is the selected registered project. Runs are
  bounded by wall-clock, turn, and tool-call limits and return structured output.
- No provider token or CLI credential is copied into Ground Space.

All discovered coding-agent runtimes advertise the same **Full write · selected
project** option. An option is executable only after that runtime is installed,
authenticated, and its adapter is qualified. Claude Code, Gemini CLI, and
OpenCode are visible foundations but remain execution-locked pending their own
adapter qualification; Ground Space never silently substitutes a raw model.

## Owner setup

Qwen Code is installed with:

```powershell
npm install -g @qwen-code/qwen-code@latest
qwen
```

Complete `/auth` in the local Qwen Code session. Then open **Agents**, refresh
provider status, add **Qwen Code**, add it to a group with a selected project,
and choose its independent approval and project-access settings.

Ground Space can alternatively connect Qwen Code to a loopback Ollama OpenAI-
compatible endpoint without storing a credential. On the ASUS, `qwen3.5:4b` and
`qwen2.5-coder:3b` passed plan/chat communication but both failed the live
file-tool qualification: they returned prose and created no files. Consequently
Qwen Code chat is available, while its full-write selector remains locked until
a tool-capable Qwen coding engine (or another authenticated provider) passes the
same real create/run/verify test.

## Security note

Qwen Code's `auto` mode applies its own safety classifier, but it is not an OS
security boundary. Use disposable or version-controlled projects until a Windows
sandbox/container boundary is qualified. Ground Space never uses Qwen Code YOLO
mode and does not grant full-write merely because the executable is installed.
