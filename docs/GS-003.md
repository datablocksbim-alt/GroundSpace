# GS-003 — Ground Space local chat prototype

GS-003 is a local browser interface over the existing Administrator queue and Ground Space bridge. It provides Chat, Agents, and Tasks views without Electron, Docker, a JavaScript build chain, or third-party Python packages.

## Start

From the repository root:

```powershell
.\tools\start_ground_space.ps1
```

The server binds only to `127.0.0.1:8765` and opens the local interface. Chat messages run automatically without an owner-token popup. Private state is stored under `%LOCALAPPDATA%\DataBlocks\GroundSpace`, outside this repository.

## Chat behavior

- Qwen supports `explanation`, `assessment`, and `code_proposal`. Conversation context is bounded to eight recent messages and 8,000 characters before being sent to the model.
- Administrator supports `help`, `list tasks`, and `status <task-id>`. These are read-only queue operations.
- Every chat request is created through `AdministratorAdapter.submit()` with explicit `approved=True`, tagged as `ground-space-local-chat` / `automatic` in the audit metadata.
- Ground Space dispatches requests asynchronously through `OrchestratorAdapter.process()` immediately after submission. No manual approval endpoint or owner-token dialog is exposed.
- The bridge still defaults to pending approval for non-chat callers; only the existing read-only Administrator console and tool-free Qwen proposal worker receive local-chat auto approval.
- The browser refreshes task state periodically for every message, including after later submissions and page refreshes, showing queued/running/retry/failure states inline.
- If a task completes before its answer is written into conversation history, the interface displays the authoritative stored answer as a fallback, without duplicating it when history catches up.

## Security

- State-changing requests require an exact localhost `Origin`, JSON content type, a SameSite cookie, and matching custom CSRF header.
- Automatic chat dispatch does not grant new capabilities: the Administrator console is read-only and Qwen remains tool-free and proposal-only; requests for write permissions are denied by the Orchestrator.
- Static files are served from a fixed allowlist; chat cannot select files, paths, processes, or shell commands.
- Qwen remains tool-free and proposal-only. The Administrator console reads only Ground Space's private queue.
- Private conversations, queue records, approval audit data, and credentials are outside the public repository.
- No cloud fallback exists, and Pyrene P2.5 is outside every worker's authority.

## Troubleshooting Qwen replies

If a message appears without a reply, read its inline queue status or open Tasks and select its task ID. `Local systems ready` only confirms the Ollama model is listed, not successful inference. `retry_pending` / `failed` indicates a worker failure or timeout; completed tasks retain their generated answers in `task.result.answer`. Automatic background refresh keeps earlier requests visible when more messages are sent.
