# GS-030 — One menu for rename and remove

**Implementation candidate only.** The existing GS-029 production app has not been restarted, replaced or modified through GitHub. GS-030 is built on `feature/gs-029-project-folder-picker`.

## Compact design

The user requested **no separate Options screen**. Projects and their nested AI group chats each have the same tiny **···** control. Tap it to show **Rename** and **Remove project** (folder row) or **Rename** and **Delete chat** (chat row) directly in one small menu.

- **Rename** → a compact text field and Cancel / Save name. Project label changes never rename or modify its ASUS folder. Chat renames preserve ID, history, models and approval modes.
- **Remove project** → the existing confirmation, with linked group chats moved to *General · unassigned*; their conversations and approvals remain intact; actual ASUS files are untouched.
- **Delete chat** → explicit confirmation, then unregister the group from navigation, **not** erase the private conversation or audit ledger. This is a conservative non-destructive delete. Chat deletion is refused while any linked queued/active tasks, Codex jobs or Co-work runs remain, including old records outside the recent UI list.
- **Cancel** in either dialog makes no change.

The old intermediate `Options` dialog was removed. Menus have touch-friendly tap areas and fit in the iPhone-sized drawer, without another page or sidebar section. The private AI chat list remains unchanged; GS-030 specifically covers registered project/group chat entries shown in the screenshot.

## Safety

All modifications are protected by Ground Space's existing private owner access, same-site Origin check and CSRF control. Server validates names/IDs and confirms the current saved name before acting. No filesystem deletion or global auto-approval is introduced. Existing project, group and chat records are loaded without migration.

## GS-030 restored-state comparison hotfix

An ASUS GS-030 preflight on 24 October 2026 reported:

```text
CONSISTENT BACKUP PASS
GS-030 check failed: GS-030 conversations data changed
```

This occurred **before any production shutdown**. The backup manifest succeeded, and the canary was isolated on port 8784. The previous verifier used direct `ConvertTo-Json` string comparison: PowerShell preserves each object's enumeration order, while Ground Space writes `conversations.json` using Python `sort_keys=True`. A restored Python process can therefore enumerate the same conversation IDs and message metadata in a different *object property order* and produce a false-positive error.

The updated `activate_gs030_asus.ps1` uses `CanonicalValue`/`StableJson` to recursively sort **object keys only**, retaining the exact original **array order, element count, text, approval modes and task states**. It continues to reject any real difference: missing histories, changed text, reordered chat messages, policies, tasks or jobs. No unsafe bypass flag was added.

`tools/test_gs030_cutover_gate.ps1` now exercises both the harmless-order and real-difference cases under Windows and Ubuntu CI. If the corrected verifier still reports a canonical data change, **stop** and investigate the stored backup/canary snapshots; do not force activation or overwrite any records.

After the final CI succeeds, refresh the *clean* detached GS-030 preview worktree to the current feature head, then run the **preflight alone first**:

```powershell
.\tools\activate_gs030_asus.ps1
```

Only after it prints `GS-030 restored-state canary PASS` should the already-approved `-Activate` step be used. The helper creates a fresh backup on each run; earlier verified backups must be retained.

## Owner-approved guarded GS-030 production activation

The owner approved GS-030 on 24 October 2026. The release candidate includes a dedicated `tools/activate_gs030_asus.ps1`, reviewed and tested through CI. **GitHub cannot restart the user's ASUS**; the owner must run it locally. Do not merge `main`, change Tailscale Serve, reboot Windows or touch Pyrene.

### Prepare the latest clean detached GS-030 worktree

```powershell
$ErrorActionPreference = 'Stop'
$source = 'D:\000_AI Project\GroundSpace-GS029-Preview'
$target = 'D:\000_AI Project\GroundSpace-GS030-Preview'
$branch = 'feature/gs-030-chat-project-management'
if (Test-Path -LiteralPath $target) {
  # Existing preview may be reused only when clean and stopped.
  $dirty = @(git -C $target status --porcelain | Where-Object { $_ })
  if ($LASTEXITCODE -ne 0 -or $dirty.Count -gt 0) { throw 'GS-030 worktree dirty: do not reset it.' }
} else {
  if (-not (Test-Path (Join-Path $source '.git'))) { throw 'GS-029 Git source missing.' }
}
if (Get-NetTCPConnection -LocalPort 8783 -State Listen -ErrorAction SilentlyContinue) {
  throw 'Close the separate GS-030 preview (Ctrl+C) before production activation.'
}
$repo = if (Test-Path -LiteralPath $target) { $target } else { $source }
git -C $repo fetch origin "+refs/heads/${branch}:refs/remotes/origin/${branch}"
if ($LASTEXITCODE -ne 0) { throw 'GS-030 fetch failed.' }
if (-not (Test-Path -LiteralPath $target)) {
  git -C $source worktree add --detach $target "refs/remotes/origin/$branch"
  if ($LASTEXITCODE -ne 0) { throw 'GS-030 worktree creation failed.' }
} else {
  git -C $target switch --detach "refs/remotes/origin/$branch"
  if ($LASTEXITCODE -ne 0) { throw 'GS-030 detached update failed.' }
}
Set-Location $target
```

### Check and activate

```powershell
# Mandatory non-disruptive preflight: checks live GS-027/028/029 identity,
# current private Tailscale route, finished task queue and Codex jobs;
# backs up private state, boots GS-030 on isolated restored data (port 8784),
# verifies unchanged conversation/project/task/policy data and all management routes.
.\tools\activate_gs030_asus.ps1

# Only if preflight says "GS-030 restored-state canary PASS":
.\tools\activate_gs030_asus.ps1 -Activate
```

The activation repeats all gates with a fresh backup, hashes the complete private-state inventory and rejects a state change or a pending/leased/approved task. Only the previously verified Ground Space process listening at port 8765 can be stopped. The new GS-030 process uses the same private state root and Tailscale Origin; the script does not change the Tailscale Serve configuration. It verifies `project_remove`, `project_rename`, `group_rename`, and `group_remove` are loaded **both on localhost and on the existing private Tailscale HTTPS endpoint**. On failure it attempts a version-matched application rollback; original backups are retained.

For a current GS-029 release, the helper pins its rollback checkout to the known predecessor `396cb87cc78bde40a93060a40ddfd06f7465b4b1`, rather than assuming the already-updated GS-029 worktree matches the resident Python process. For GS-027 or GS-028, it requires the original matching release checkout. Unsupported or ambiguous live releases fail closed.
